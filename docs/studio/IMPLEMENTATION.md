## Scope and precedence

UAP remains the product. `New` sets the long-term target (six references, persistent companions, isolated work and eventual commercial operation). The earlier redesign blueprint and checklist constrain the first visible release: an original, Nightly-led agent workspace over the current runtime, not a platform migration. The [v6 checklist](../v6-blueprint/CHECKLIST-v6.md) still owns existing requirements and IDs; the [architecture freeze](../architecture/ARCHITECTURE-FREEZE.md) still owns authority boundaries. The freeze's dated implementation-status table is not a current inventory. No new backlog replaces v6 or closes its items. See [input pins, scope deltas and all 19 workstreams](TRACEABILITY.md).

**First release:** one roster, one selected-agent stage and one optional contextual inspector. Original UAP plush portraits; real Chat and reachable Work, Files and Automations surfaces using data the existing backend can actually expose. Show a reason when a capability is unavailable; no fake counts, dummy actions or fabricated active state. Keep the existing signed-in routes, session ownership, provider choices, SID and permission behavior intact. No parallel navigation rail, alternate issuer, donor runtime, new device-control surface, shared host sold as isolated computer, hosted account enrollment, or billing activation.

**Later releases:** earn separate gates for receipt-linked workflows and durable ingress, isolated execution and Vault, broader AG-UI and devices, verified sovereign adapters, and the commercial platform. `New`'s proposed directory tree and desktop/mobile clients are targets, not a mandate to move current code. Build one vertical slice at a time in the owning UAP modules. No new service ports or production changes belong to this docs task.

## Ownership and current seams

| Doctrine field | Existing seam → planned use |
|---|---|
| 1. Niche | UAP workspace and control plane. Show state, submit authenticated intentions, and preserve ownership of actions outside the client. |
| 2. Core language | TypeScript: existing Hono API + React/Vite and typed projections. CSS/tokens and platform-native web controls; no framework replacement. |
| 3. Supporting components | Rust `agentos-policy` authorizes privileged effects; Elixir `agentos_worker` supervises durable jobs; PostgreSQL holds the durable ledger and outbox. Preserve the seven specialist language assignments (Rust, Julia, Elixir, Clojure, Python, Go, Move) with TypeScript as the surface; require only the services a run needs. Wasm is a target, not a language. |
| 4. Agent model | One persistent SID per activated principal. A template, imported pack, portrait, device key, Vantage account or model is not a principal or a grant. A child has a distinct SID and lineage, not copied grants. Keep native Ọmọ Kọ́dà identity and UAP SID related but distinct. |
| 5. Interfaces | Keep authenticated REST, `/mcp`, `/api/events` SSE, and existing signed-in/public-call contracts. Use one server projection for authorized UI and agent API/MCP reads; publish scoped schema/discovery before new UI-only affordances become product capabilities. Human-only approval remains human-only. |
| 6. Protocols | Existing HTTPS/session or scoped capability auth; optional Nostr for existing signaling/identity, not durable truth. AG-UI is an opt-in mapping at the UAP event edge, not an execution channel. Freenet not required for Studio; no new chain or relay dependency. Version internal service contracts and preserve external wire formats. |
| 7. Authority | SID issuer and Ọmọ Kọ́dà own their respective identity records, Hermes reasons, Rust authorizes, Elixir supervises, and the Postgres ledger decides durable work state. SQLite still serves legacy paths; no implied storage cutover. Proposed Vault brokers scoped secrets, GIX owns provenance for its records, Vantage owns its network/work records, and economic settlement stays with authorized sovereign adapters. An eventual UAP usage ledger is not a settlement ledger. |
| 8. Failure | Mark stale/disconnected/not configured/unsupported distinctly. Reconnect by confirmed cursor or snapshot, never by resubmitting on receipt loss. Once an external outcome is unknown, stop at `UNCERTAIN` and reconcile; reject stale leases and approvals. A failed configured provider does not silently switch; an absent optional provider may use an explicitly supported local path. |
| 9. Validation | Pin build SHA and environment. Separate source checks, isolated fixtures, staged real dependencies and release evidence. Prove persistence/recovery, ownership, revocation, no leaks, real effects and safe rollback on disposable data; no offensive workflows. |

```text
Web / authorized agent client
    -> UAP Hono routes / MCP / event projections
       -> current direct chat: SQLite transcript + agent/loop enqueue -> Hermes
       -> durable work: Rust permission boundary + Postgres jobs/outbox <-> Elixir
       -> existing SID materialization or separately authorized Ọmọ Kọ́dà birth
       -> optional Vantage registration; other ecosystem links only after conformance
```

- `server/src/index.ts` mounts `/api`, `/api/rooms`, `/api/v6` and `/mcp`. `server/src/routes.ts` owns `/api/events`, direct messages (`POST /api/bots/:id/messages`) and approval responses. Direct message dispatch still reaches legacy `enqueue()` for the Hermes lane. Do not claim that a PostgreSQL repository, queue adapter or outbox makes ordinary chat durable.
- `server/src/routes-v6.ts` owns SID materialization and birth (`POST /api/v6/sid/materialize`, `POST /api/v6/sid/omokoda/birth`, `GET /api/v6/sid/omokoda/birth/:botId`) and owner-scoped MCP catalog paths. Reuse `materializeSidBot` and the existing birth coordinator. Confirm scope and consent; duplicate client retry must replay a confirmed outcome, not create an agent, and ambiguous birth is held for reconciliation. A Vantage registration failure does not undo a confirmed birth.
- `web/src/main.tsx` handles `/call/<token>` separately from `App.tsx`. Preserve that boundary and do not expose tokens. `App.tsx` already uses `Sidebar` and `DetailsPanel`; the latter defaults to Operate and renders `AgentDesk`. `WorkspaceRail.tsx` exists but is not mounted by `App.tsx` at this pin. Improve the actual roster/stage/inspector, not an unused component.

## Visible release specification

- **Composition:** desktop roster (260–280 px), fluid stage, inspector (336–368 px when space allows); below 1200 px collapse the inspector to a drawer; at phone widths use one stage, roster drawer, inspector bottom sheet and one dismiss layer. Preserve selection, safe-area/keyboard behavior, IME submit semantics, context-safe drafts and keyboard focus restoration. Use 360, 390, 768, 1024, 1440 and 1920 px acceptance widths. Keep the stage useful without the inspector.
- **Stage:** agent avatar/name and sourced status; Chat/Work/Files/Automations are selected-agent facets, not another sidebar. Keep transcript scrolling anchored to row IDs through reconnect and prepend; provide send/stop, inline approvals, outcome-first tool rows and existing scoped artifact access. In the inspector show Operate by default, with Identity/Activity in context and one-click Computer/Voice/Agent from the header. Distinguish no data from failure/stale/unconfigured and expose a real next action.
- **Visual system:** use the earlier warm charcoal/porcelain/soft-green proposal as the initial palette; compare `New`'s Obsidian/Graphite/Porcelain/Sage/Lilac palette during design review, not as a competing token system. Use a consistent contrast-tested semantic palette, 44 px primary touch targets and WCAG 2.2 AA target. A launch screen needs empty/loading/failure states, keyboard and 200% zoom checks, reduced motion and screenshot evidence. Prefer a matte, textural workspace rather than gratuitous gradients, glass or card grids.
- **Plush:** author an asymmetric felt seed-pod family with original shape, stitched detail and restrained movement. Keep editable masters and rights/provenance records; bake light assets at 24/32/44/64/112 px, keep existing avatars/fallbacks readable, and defer GPU-heavy rendering. Persist only approved asset/variant/palette references on the owned profile; portrait choice never mutates SID, model, grants or enrollment. Map idle/running/queued/approval/blocked/offline/completion to real events; listen/speak only when real media state supports it. Never equate offline/failure with sleep. Prefer a clear static equivalent in reduced motion. Proposed budgets: ≤100 KiB default mascot payload, ≤10% initial JS gzip growth vs same-host baseline, and CLS ≤0.1 on the agreed fixture; measure before enforcing.
- **Product acceptance:** signed-in fixture captures at all widths plus real staged user journeys. Score original identity 20, composition 15, typography 10, interaction/motion 15, function 20, accessibility/responsiveness 10, performance/reliability 10; proposed minimum 90/100. No score overrides rights, security, accessibility or functional failure. Use brand/motion/frontend owners and independent QA, rights, security and release reviewers; do not self-grade. Reuse the [role review](../architecture/ROLE-REVIEW.md) and [build protocol](../BUILD-PROTOCOL.md).

## Contract increments, not candidate routes

1. **Work/Activity/Files:** project owned job/row/decision/receipt IDs, typed status, sanitized reason and opaque scoped cursor; separate proposed, permitted, started, confirmed and uncertain. Server checks scope again when reading a file or acting on a job. Bound output, make unsupported previews explicit, and never emit secrets, private memory, absolute paths or raw tool arguments. Reconnect by snapshot for gaps and dedupe redelivered events. Record tenant/SID, causation and timestamps in restricted evidence, not in a public stream.
2. **Approval preview:** candidate rule + bounded date window/limit → matched/changed/unchanged/insufficient evidence with allowlisted samples. Existing view permission required; never reconstitute missing parameters, mint a permit, or save a rule as a side effect. Human approval binds an actual intent; it is not proof of effect.
3. **Durable text ingress:** first cohort of direct turns only. Atomically persist admitted intent with a tenant-scoped idempotency key and reject reuse for different input. Preserve existing transcript/read contract. Worker settlement uses current epoch and receipts. Pause, interrupt and cancel are distinct; rooms, routine, tool delegation and voice stay on existing paths until independently proven.
4. **External AG-UI:** start with opt-in, operator-configured text-only streaming, validation, bounded events, cancellation/deadline and safe refusal. The UAP-owned conversation remains authoritative, and external events confer no tool access or completion. Structured cards/forms and remote agent interoperability need a later schema + authority gate; no arbitrary browser code or remote execution channels.
5. **Sandbox/Vault/devices:** isolation under the existing policy and supervision boundary before rollout. Distinguish preview from explicit takeover; expire and revoke control/credential leases, release handles on teardown, and test independent tenants and agents. Secrets are write-only at UI/API, scoped at use, and absent from receipts/logs. Device pairing needs one-time expiring enrollment, explicit grants, revocation, and per-device/tenant proof before it can expose data or input. Existing public call/voice is not pairing or PSTN.

### Blockers and defaults

- **Baseline drift:** `New` and the earlier documents report different development/deployment snapshots. Only the isolated product parent is pinned here. Recheck exact candidate, deployed branch and served bytes in a separately approved release review. Do not merge an unrelated development branch just to make SHAs match.
- **Isolation:** this baseline is single-owner. RLS modules, local displays/VNC, `UNCERTAIN` fixtures and portable leases do not demonstrate sandbox/tenant/credential isolation. Require real tenant-bound sandbox/process/storage separation, quotas, default-deny egress and teardown/restore evidence before externally enrolling tenants.
- **Managed Ọmọ Kọ́dà:** preserve existing direct mode; historical plan reports missing managed capability and an unresolved kernel gate, not a fresh observation. Require a green kernel audit and native bind/restore staging evidence, then roll compatible kernel → UAP → Vantage handoff, with capability preflight and paired rollback. Studio's first release cannot depend on this.
- **Devices and communications:** mobile web parity is first; native/ambient operation and imported agent migration later. No claim of equivalent capability across devices until enrollment/expiry/revocation, scoped access and actual sessions are proven. Phone numbers, email account provisioning and paid providers need separate operator/provider approval.
- **Billing and ecosystem:** in-memory tier or permission tests do not equal authenticated metering, a ledger or settlement. Default to deny for real charges/mainnet. Each adapter needs a pinned contract, an accountable owner, scoped identity and consent, a disposable real-dependency test, outage behavior and rollback; see the companion inventory. Missing rights, protocol access or provider proof is a release blocker for that lane, not for the visible shell.

**Final product proof:** an authorized user creates a companion, keeps the same SID through an allowed provider/device change, assigns and inspects real work with receipts, uses only approved tools and a genuinely isolated computer, receives safe structured results, and exercises privacy/revocation and recovery without lost identity or duplicate effects. Communications, ecosystem and billing claims require their own verified lanes. A source-map total is not this proof.
